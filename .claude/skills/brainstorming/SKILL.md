# Brainstorming

Не пишем код, пока не проверили, что понимаем задачу правильно.

1. Переформулируй задачу своими словами — что должно получиться на выходе.
2. Если есть развилки (варианты реализации, где нет очевидно единственного
   решения) — задай уточняющий вопрос вместо того, чтобы угадывать.
3. Предложи короткий план (2-4 пункта): что меняется, в каких файлах.
4. Дождись согласия владельца перед тем, как менять код.

Пропускай этот шаг для мелких, однозначных правок (опечатка, лог, константа).
